# Canon D

> Целью обучения является не вооружение знаниями, не накопление их, а формирование умения действовать со знанием дела.
> Пётр Яковлевич Гальперин.

> Концептуального знания не достаточно. У вас должна быть убеждённость, происходящая из собственного опыта.
> Максим Дорофеев.

Консольная утилита для активного [интервального повторения](https://ru.wikipedia.org/wiki/Интервальные_повторения). 

Большинство систем интервального повторения используют "пассивные" карточки. Это значит, что их нужно просто прочитать и потом решить, насколько хорошо запомнилась информация на ней. На самом деле тут нужно приложить усилие для вспоминания, и именно это усилие -- необходимый элемент интервального повторения. 

Однако мозг старается избежать этого, и "пассивные" карточки легко становятся формальностью, не дающей реального эффекта. "Активная" карточка означает некое действие, в данном случае -- написать пропущенный текст. Это заставляет мозг прикладывать усилие и вспоминать.


## Смысл названия

> Канон (искусство) — совокупность норм и правил в искусстве.

> Канон (наука) — совокупность основополагающих законов, норм и методов в научных знаниях.

Canon D -- Canon for Development -- основополагающие базовые навыки программиста. (_Может быть это слишком амбициозное название для текущей версии. Но я планирую развить приложение в нечто большее_).

А ещё Canon D (Канон ре-мажор) -- это широко известное произведение немецкого композитора Иоганна Пахельбеля. По нему сделано тысячи разных каверов. Например, [этот в стиле Rock](https://www.youtube.com/watch?v=XZgiNnGB8m4).


## А зачем это, когда есть ИИ, который всё знает, всё помнит и всё подскажет?

Мы тренируем мозг примерно так же, как спортсмены тренируют мышцы -- с помощью упражнений, которые создают искусственную нагрузку. Спортсмены бегают и подымают тяжести. Люди умственного труда запоминают факты и решают задачи.

Наличие автомобиля не заменяет пробежки. Наличие грузчиков не заменяет тренажёрный зал. ИИ не отменяет необходимость тренировать свой естественный интеллект. 


## Использование

Соберите проект с помощью Go 1.25 или новее:

```sh
make compile
```

Запустите программу с колодой:

```sh
./canon_d --deck ./decks/golang.md --limit 10
```

Или выберите несколько колод из папки:

```sh
./canon_d --decks ./decks --limit 10
```

Используйте либо `--deck`, либо `--decks`. Список содержит нескрытые обычные файлы
`.md` в порядке имён, без поиска во вложенных папках. Стрелки вверх/вниз перемещают
курсор, пробел выбирает колоду или снимает выбор, Enter начинает обучение.
Изначально ничего не выбрано. Пустые и недоступные для чтения колоды показаны с
причиной недоступности и не выбираются. Если подходящих колод нет, программа
сообщает об ошибке. Количество карточек и обучение используют содержимое,
загруженное при открытии экрана. Для загрузки изменений перезапустите программу.

Карточки выбранных колод объединяются и располагаются в случайном порядке с учётом
сохранённых приоритетов, затем применяется общий
`--limit` (по умолчанию 10). Лимит должен быть положительным; если он больше числа
карточек, используются все карточки. Квоты на каждую колоду нет, поэтому выбранная
колода может не попасть в раунд. Над текущей карточкой показано имя её исходной
колоды, в том числе при повторении ошибок. Управление на экране завершения и при
повторах остаётся прежним.

Требуется терминал размером не менее 20 столбцов и 11 строк. Горизонтальная линия отделяет
неподвижный заголовок карточки от её прокручиваемого содержимого. Для прокрутки используйте PgUp/PgDown.
На экране выбора колод PgUp/PgDown перемещают курсор на страницу; заголовок,
количество выбранных колод и подсказки остаются видимыми. Ctrl+C завершает программу
на любом экране.

Статистика обучения автоматически сохраняется в `.canon_d.csv` в папке колод
(при `--deck` — в родительской папке файла). Каждая строка содержит:

```csv
deck,card_header,shows,correct_answers,incorrect_answers
```

Счётчики показов, правильных и неправильных ответов накапливаются между запусками
и раундами повторения. Показ учитывается один раз, когда карточка становится видна;
перерисовка, прокрутка и изменение размера терминала не добавляют показов.
Каждый введённый ответ на пропуск увеличивает соответствующий счётчик. Карточки
для чтения добавляют только показы. Строка определяется именем файла колоды и
полным иерархическим заголовком карточки. Одинаковые заголовки в одной колоде
объединяют статистику; переименование колоды или заголовка начинает новую запись.

Сохранение происходит после каждого раунда и при Ctrl+C, включая уже введённые
ответы на незавершённой карточке. Принудительное завершение может потерять изменения
с последнего сохранения. Некорректный CSV останавливает запуск; ошибка сохранения
завершает программу с сообщением и сохраняет прежний файл. Одновременно использовать
историю одной папки может только один запущенный экземпляр программы. Скрытый файл
`.canon_d.csv.lock` остаётся рядом с CSV; его наличие не означает, что программа
запущена. Оба файла исключены из Git в этом репозитории.

Оба режима обучения проверяют все строки истории до открытия TUI, включая записи
удалённых карточек. Отсутствующий файл допустим; существующий пустой файл считается
ошибкой, а файл только с заголовком допустим. Проверка требует точный заголовок из
пяти столбцов, уникальные идентификаторы, непустые поля идентификаторов в UTF-8 без
управляющих символов и десятичные беззнаковые 64-битные счётчики. Поля идентификаторов
не могут состоять только из пробельных символов. Имя колоды должно быть именем файла
без разделителей каталогов. Положительное число ответов требует хотя бы одного показа;
число ответов на показ не ограничено. Допустимы стандартное CSV-экранирование,
пустые строки, LF/CRLF и ведущие нули в счётчиках. Регистр и пробелы в идентификаторах
учитываются при сравнении.

Первая ошибка останавливает запуск с кодом `1`. Сообщение в stderr содержит путь,
физический номер строки, имя поля, если применимо, и причину. Для дубликатов также
указывается первое вхождение. Файл не изменяется, блокировка освобождается. Пример:

```text
load statistics: decks/.canon_d.csv:3: invalid correct_answers: positive answers require shows > 0
```

Полные правила описаны в
[решении о проверке CSV истории](./docs/adr/0008-history-csv-validation.md).

Перед каждым сохранением те же правила идентификаторов и согласованности счётчиков
применяются к итоговым суммам, включая записи удалённых карточек. Некорректные данные
отменяют всё сохранение и останавливают обучение, сохраняя прежний файл. Сообщение
указывает первую ошибочную запись в порядке сортировки по колоде и заголовку: путь,
колоду и карточку в кавычках, поле и причину. У новых данных нет номера строки CSV.

Парсинг при обучении по-прежнему допускает ошибки оформления; явная проверка
колоды не обязательна.
Идентификатор, который нельзя сохранить, например пустой полный заголовок или
заголовок с управляющими символами, вызывает ошибку при следующем сохранении,
а не при загрузке колоды. Идентификаторы не нормализуются, ошибочные строки
не пропускаются молча. Пример:

```text
save statistics: decks/.canon_d.csv, deck "network.md", card "": invalid card_header: must contain non-whitespace text
```

Начальный отбор отдаёт предпочтение новым карточкам и карточкам с большим числом
ошибок относительно правильных ответов. Вес старой карточки равен
`(incorrect_answers + 1) / (correct_answers + 1)`. Карточка без истории или с обоими
счётчиками ответов, равными нулю, считается новой. Её вес вдвое больше максимального
веса старой карточки среди доступных для отбора. Если все карточки новые, отбор
равновероятный. Карточки для чтения сохраняют приоритет новых, пока их счётчики
ответов равны нулю; число показов на вес не влияет.

Больший вес повышает вероятность попасть в раунд и появиться раньше. Каждая
карточка может попасть в начальный раунд только один раз; отдельные экземпляры
карточек с одинаковыми заголовками сохраняются. Например, при одной новой и одной
старой карточке и `--limit 1` вероятность выбора новой равна двум третям. Оба режима
запуска используют статистику, загруженную в начале запуска. В раундах повторения
все экземпляры карточек с ошибками по-прежнему перемешиваются равновероятно.

Можно создавать свои карточки; пример — [decks/network.md](./decks/network.md).

Проверьте колоду без запуска TUI и обращения к истории обучения:

```sh
./canon_d --validate-deck ./decks/network.md
```

Используйте этот флаг отдельно, без `--deck`, `--decks`, `--limit` и позиционных
аргументов. Проверка выявляет пустые колоды и конечные карточки, некорректные или
повторяющиеся заголовки, некорректные ответы в обратных кавычках, пустые и незакрытые
блоки кода. Пустые заголовки разделов с дочерними карточками и карточки для чтения
допустимы. Текст перед первым заголовком вызывает предупреждение. Эти строгие
проверки не меняют обычный режим обучения.

Отчёт выводится в stdout: имя файла, номер строки (начиная с единицы), затем общее
число карточек, карточек для чтения, предупреждений и ошибок. Например, две карточки
для чтения с одинаковым заголовком на строках 1 и 3 дают:

```text
example.md:3: error: duplicate card path: Card (first occurrence: example.md:1)
example.md: 2 cards, 2 reading cards, 0 warnings, 1 errors
```

Код завершения — `0`, если ошибок нет (предупреждения допустимы), `1` при ошибках
валидации и `2` при некорректных аргументах или ошибках доступа к файлу. Последние
выводятся в stderr. Полные правила описаны в
[решении о проверке колод](./docs/adr/0007-deck-validation.md).
